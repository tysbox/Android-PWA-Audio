Biscene DSPSystem V6.2 Production

ポータブル環境適応機能を統合した、次世代プロフェッショナル・ネイティブ・マスタリング・エンジン

🚀 1. コア・ネイティブNDK ＆ USB ビットパーフェクト直結パイプライン

ARM NEON SIMD 演算に最適化された 96kHz / 32-bit Float 精度マスタリング処理基盤と、AudioFlinger を完全バイパスする USB 直結 E2E ビットパーフェクト出力。

  • NEON SIMD 96kHz/32-bit Float パイプライン: 96,000Hz / 32-bit Floating Point の全マスタリングDSP処理を ARM NEON 命令で並列高速化。
  • サンプル精度 ギャップレス再生パイプライン (Gapless Playback Engine):
    ・`SinkCarrier` 引き継ぎアーキテクチャ トラック終了時に音声出力シンク (`AudioTrack` / USB Direct) を破棄せず保持。後続トラックが前曲のバッファ末尾へ直結し、無音隙間（ギャップ）やノイズのない完璧なギャップレス再生を実現。
    ・`LookaheadScheduler` 先読みプリウォーム 曲終了の 5 秒前に次曲を自動検出し、バックグラウンドでデコーダー (`PrewarmCache`) を先読み初期化。
    ・Fade-Hold 末尾排出 1 チャンク保留により真の最終チャンクを確定し、フェード（最大 3ms / 288 フレーム、実測 1114-1115 フレーム）を全 DSP/シンク経路で排出。全トラックが正確なゼロ振幅で終了。
    ・Pause→Flush→Play 引き継ぎリアーム 採用シンクを `pause()→flush()→play()` で再アームし、前曲の残留音声を確定的にクリア。
    ・2秒バッファフロア `Math.max(min*4, 1572864)` バイト (196,608 フレーム ≈ 2.0秒) が実測最悪 1.3 秒の park 期間を保護し、アンダーラン グリッチを排除。
  • デュアルパス 絶対位相反転機能 (0° Normal / 180° Phase Reverse):
    ・DSP ON モード C++/NDK 層 (`NativeDspChain` - `nativeSetPhaseInverted`) にて 1ms クロスフェードによるノイズフリーな 180° 絶対位相反転。
    ・DSP OFF (ビットパーフェクト) モード `JavaPhaseInverter` により、USB パッキング直前の生の PCM データに対してビット深度・サンプルレート精度を保ちながら 180° 位相反転を非破壊適用。
  • V6.2ナイトモード・ダイナミクス・コンプレッサー (`DynamicsCompressor`):
    ・ジェントル フィードフォワード RMS 圧縮 2:1 レシオ、−24dB しきい値、20ms アタック / 300ms リリース、−9dB 最大減衰フロア — ポンピングなしの静かなナイトリスニング。
    ・~10ms ランプ安全トグル 圧縮ミックスを ~10ms でランプ（PhaseInverter パターン）、切替時にポップは原理的に発生しない。無効時は純粋パススルー（コストゼロ）。
    ・ロックフリー ＆ ゼロアロケーション `setEnabled()` は relaxed atomic store（任意スレッドから安全）、`process()` は音声スレッド専用・ヒープ割り当てなし。
    ・ビットパーフェクト純度 Output EQ ダイヤルが NIGHT の時のみ `night: true` を送信。`bypass: true`（ビットパーフェクト直結）パスはこの分岐に到達しないため、純度は設計上保証。
  • 4点 Catmull-Rom リニアフェーズ・リサンプラー (`RateConverter`):
    ・Catmull-Rom 3次スプライン補間 入力音源 (44.1k/48k/88.2k等) を 96kHz へ高精度再サンプリング処理。
    ・Linear Phase ＆ Zero Pre-Ringing 時間対称な 4 点多項式補間カーネルにより、完全な直線位相特性と群遅延歪みゼロを実現。プリリンギング（事前前鳴りノイズ）を完全に排除し、音源のアタック立ち上がりトランジェントを忠実に防護。
  • USB 直結出力モード (AudioFlinger バイパス):
    ・DSP オフ時 (E2E ビットパーフェクト直結) End-to-End (E2E) ビットパーフェクト直結伝送。音源本来のサンプルレートおよび元のビット深度（16-bit / 24-bit / 32-bit）のまま、1 ビットも変更・改変・再サンプリングを行わずに外部 USB DAC へ完全無加工ダイレクト送信。
    ・DSP オン時 (96kHz / 32-bit マスタリング ＆ 24-bit ダウングレード対応) `NativeDspChain` を通過し 96kHz / 32-bit Float 精度で高品質演算。接続先の外部 USB DAC が 32-bit 非対応の場合は、DAC のハードウェア限界に合わせ自動的に 24-bit (`UsbPcmPacker`) へ安全ダウングレード。
  • Direct NDK Isochronous USB エンジン (`UsbDirectEngine`):
    ・C++/NDK 層から Linux `ioctl` を通じて USB 等時性 URB (`USBDEVFS_URB_TYPE_ISO`) を直接送信。Android `AudioTrack` や OS リサンプラーを一切通過しません。
    ・動的カーネルドライバー解放＆再結合 USB DAC 接続時に `USBDEVFS_DISCONNECT_CLAIM` で標準の `snd-usb-audio` ドライバーを自動切断。デバイス解放時には `USBDEVFS_CONNECT` で自動再結合し、システム音声の復元を完全自動化。
    ・UAC1 / UAC2 ディスクリプター解析 USB Audio Class 1 / 2 ディスクリプター構造を直接解析し、DAC が対応するサンプルレート・チャンネル数・ビット精度を自動検出。
  • トリプル出力アーキテクチャ:
    ・USB Direct Mode 外部 USB DAC への USB Isochronous 直結出力（DSP オフ: E2E ビットパーフェクト / DSP オン: 96kHz/32bit・24bit ダウングレード）。
    ・System Direct Mode Android `AudioTrack` (96kHz Float) へ直接書き込みを行う直結再生。
    ・HTTP Proxy Mode 内蔵プロキシ (`http://127.0.0.1:9600/pcm`) による 32-bit Float PCM 配信。
  • Lock-Free Zero-Allocation スレッド: 音声再生スレッドでの動的メモリ割り当ておよびロック取得を完全に排除し、音飛びを追放。
  • True Peak セーフティ・リミッター: 4倍オーバーサンプリング FIR と 1.0ms 先読みにより、DAC でのインダーサンプル・ピーク (ISP) クリッピングを物理防護。
  • Hi-Res ＆ DSD/DSF ネイティブデコーダー:
    ・DSD (`.dsf`, `.dff`) 1-bit ビットストリームデコード (`DsfDecoderV2`) および FLAC, WAV, ALAC, AAC, MP3, M4A 多フォーマット対応。
    ・176.4kHz 動的デシメーション 全 DSD レート (DSD64/128/256/512) を 176,400Hz ハイレゾ PCM へデシメーション (`decimR` = 16/32/64/128)。
    ・クリーン末尾ブロック処理 不完全な末尾ブロックを `drain()` で安全破棄（ダーティフレーム 0 を実証）； DSD64 デコードを実測 7.81 倍リアルタイム (t25)。

📐 2. 空間 ＆ 仮想音響マトリクス (5x5)

物理頭部音響モデリングに基づく精密な音場角度と距離感の物理再現。

  • Unity-Gain クロスフィード（Woodworth ITD、ネイティブ `SpatialMatrix`）:
    ・6段角度ダイヤル (OFF / 15° / 30° / 45° / 60° / 90°) ミキサー行 `X-FEED ANGLE` ダイヤルで方位角を選択。OFF は完全ビット透過パススルー。
    ・サブサンプル分数 ITD 遅延ライン Woodworth モデル遅延 (`getItdSamples(angle)`) を線形補間で分数サンプル精度に対応； クロストーク成分を遅延させ、固定 0.26 の unity-gain クロスフィード係数で反対チャンネルへ注入（直接パスは 1.0 を維持 — バイパス比の音量損失なし）。
    ・クロストークへの頭部シャドウイング ネイティブ IIR シェルビングフィルタ (`shadowL`/`shadowR`) がクロスフィード成分のみに周波数依存 ILD を適用。
  • Spherical Head Shadowing: 周波数依存の頭部回折 (ILD) をネイティブ IIR フィルタで高度にエミュレート。
  • 距離軸インテリジェンス（ミキサー `DISTANCE` ダイヤル: OFF / INTIMATE / NEAR / NORMAL / FAR / DEEP）:
    ・Proximity Effect 近接聴取時における球面波の低域ブースト効果。
    ・Air Absorption 遠方音場における高域空気減衰特性のリアルタイム模倣。
    ・環境補正フィルタ (`envL`/`envR`) クロスフィード後の同一 5x5 マトリクスパスでチャンネルごとの IIR 補正を適用。
  • Virtual Acoustic 境界吸音プロファイル: Studio, Wood, Glass などの材質吸収特性に応じた音響空間プリセット。

🌙 10. ポータブル環境適応 (V6.2 新設 — 全機能実装済み)

モバイル環境の変化（DAC 接続、ネットワーク状態、発熱、省電力）に自動適応する 5 大機能。音響アーキテクチャの純度・堅牢性は一切損なわれません。

  • N1ナイトモード（Output EQ ダイヤル統合型）:
    ・Output EQ ダイヤル統合 NIGHT 位置（最終段、CRYSTAL の後）で静的ナイト EQ カーブと動的 `DynamicsCompressor` を統合 — ダイヤルを NIGHT に回すだけで完全なナイトリスニング体験。
    ・ジェントル・ダイナミクス 2:1 / −24dB / 20ms-300ms / −9dB フロア； ~10ms ランプ安全トグル； ロックフリー、ゼロアロケーション、OFF 時は純粋パススルー。
    ・stale 状態防止 全 DSP 更新で `night` を明示適用（非 NIGHT 位置では false）— ダイヤルを動かしても stale ON が残らない（tube リセットと同一パターン）。
  • N2LUFS ラウドネス正規化:
    ・`LoudnessAnalyzer`（純 JVM） 簡易 K-weighting 近似（1-pole HPF ~40Hz ランブル除去 + 1-pole ハイシェルフ ~1.5kHz +4dB 耳感度補正 + 平均二乗）； `gain = −18（ReplayGain 2.0 基準）− 測定レベル dB`、±12dB クランプ； 無音 → 0dB 安全デフォルト。
    ・エンドツーエンド トリガー配線 音声スレッドが最初の 5 秒の raw PCM を収集（コピのみ・事前確保バッファ）→ IO プールで分析（R4 順守）→ `onLoudnessMeasured` を 1 回だけ発火（default メソッド — シグネチャ安全）→ 既存 `playbackTime` チャンネルで Web 層へ → `setTrackLoudnessDb()` が DSP ペイロードを再送し、測定ゲインを現トラックに即時適用。
    ・新規 JNI ゼロ ゲインは `updateDspInternal()` で `preampDb` に加算 — 既存 update() が更新時に `preampLin = 10^(preampDb·cs/20)` を計算（recomputeMakeup() 慣習： 更新時計算、音声スレッドは読み取りのみ）。
    ・実測による係数バグ修正 初期の逆転（減衰）係数形式が平均二乗を崩壊させた（GainProbe: 0.95 サイン波が +91.7dB = 逆方向）； 1-pole ステップ形式で正しいゲインを実証（0.95 → −12 クランプ、0.25 → −10.78、0.03 → +7.63、0.0005 → +12 クランプ）。
    ・ビットパーフェクト純度 bypass ペイロードは `preampDb: 0` で `loudnessDb` を運ばないため、USB ビットパーフェクトパスは構造上無影響。
  • P1Auto-DAC プロファイル＆プロテクトシステム:
    ・`DacProfileStore`（SharedPreferences 永続化） VID:PID キーング（ポート/シリアル除外 — 同一 DAC モデルならどのポートでもキャッシュヒット）； `load()` は無効/欠落/パース失敗で null（呼び出し側はレガシープローブ = 安全デフォルト）； `save()` は configure+start 成功後のみ（一時的失敗は記録されない、PrewarmCache 準拠）； キルスイッチで再ビルドなしに復帰。
    ・ゼロレイテンシー再適用 `initUsb()` がキャッシュ済み bitDepth を `configure()` の前に再適用（レートはソース/bypass 状態に依存するため不変）。
    ・ソフトスタート・アンチポップ・ランプ `writeUsbChunk()` が 8 チャンク（~20–50ms）でゲイン 0→1 をランプ、パック前の float サンプルに適用（パック後バイトへの乗算は破壊するため）； armed 1.0 で定常状態は 1 回の整数比較、ホットパス無影響； ランプは全 USB（再）構成で再装填 — まさにポップ起きやすいドライバー (再)バインドの瞬間； AudioTrack パスは無影響（ポップは USB ドライバーリバインド固有）。ロックフリー: `AtomicInteger` を音声スレッドのみが増分（R4 順守）。
  • P2ネットワーク耐性可変プリロール:
    ・`LookaheadScheduler.setWindowMs()` `windowMs` を volatile 化し 3000–15000ms にクランプ； デフォルト 5000ms は不変（既存テストの契約）。単一 volatile 書き込み — ロック不要、torn-read 安全、任意スレッドから安全。
    ・`NetworkStateMonitor` `registerDefaultNetworkCallback`（実績のある DualSsdpBridge パターン）でリンク品質をウィンドウへマッピング — 検証済み Wi-Fi → 5000ms（レガシーデフォルト）、検証済みセルラー → 8000ms（ハンドオーバー + 高 RTT）、劣化/未検証/リンク消失 → 12000ms（遅いオープンでもウィンドウ内に着地）。
    ・WindowConsumer パターン per-listener スケジューラーは構造的にトラックごとなので、モニターはプラグインレベルの volatile フィールドを更新し、各新トラックのスケジューラーが生成時に現在のウィンドウを採用（インスタンス初期化子）。
    ・安全性 全失敗は現在のウィンドウを維持； キルスイッチで解除 + デフォルト復帰； コールドスタートで即時適用； 音声パスには触れない。
  • P3サーマル＆バッテリー連動スマート DSP スケーラー:
    ・`PowerStateMonitor` `OnThermalStatusChangedListener`（API 29+、ガード付き）+ `ACTION_POWER_SAVE_MODE_CHANGED` 受信； POLICY のみ — Policy enum を計算してコンシューマーへ渡す； 音声スレッド・ネイティブ・ロックには触れない。
    ・ポリシーマッピング（純関数、JVM テスト可能） 省電力 → MUTE_AMBIENCE（ハード制約、サーマルに優先）； サーマル ≥ SEVERE → MUTE_AMBIENCE（即時）； サーマル ≥ MODERATE → REDUCE_AMBIENCE（最も優しい第一段階： 最も CPU を喰う段階 — 1024-tap FIR + フィードバックテイル — の wet レベルを半減）； LIGHT/通常 → NONE（フル DSP、P3 前と完全同一）。
    ・冷却時の正確な復元 `lastUserAmbIntensity` が各 DSP ペイロードからユーザー自身の ambience 強度を記憶し、デバイスが冷めたら正確に復元。
    ・新規ネイティブ経路ゼロ ポリシーは既存 `updateDsp` ペイロード経路で適用（churn ガード: 変化 < 0.5 で再送なし）； トーンシェーピング、ナイトコンプレッサー、リミッターは無影響。
    ・キルスイッチ (`setEnabled(false)`) 両リスナーを解除して NONE を通知 — 再ビルドなしに P3 前へ 1 行ロールバック（R5 準拠）。
